## 核心改进方案

### 1. 架构简化
**当前**：9个转换器，6个双向转换
**目标**：7个转换器，4个双向转换

**转换路径**：
```
Chat Completions (中间格式)
    ↓ ↑
Responses API
    ↓ ↑
Anthropic Messages API
```

### 2. 上下文完整性保护
**核心原则**：
- 最小化转换：只转换必要的字段
- 保留元数据：保留所有元数据字段
- 保持顺序：保持消息的原始顺序
- 保留空值：保留空值字段，不进行过滤

**禁止的操作**：
- 禁止压缩：不压缩消息内容
- 禁止过滤：不过滤空消息或空字段
- 禁止重排：不重新排列消息顺序
- 禁止聚合：不聚合多个消息为一个

### 3. 深度思考支持
**标准化参数**：
```json
{
  "reasoning_effort": "low|medium|high|max|minimal|none",
  "thinking": true|false
}
```

**提供商映射**：
- Anthropic → `thinking` 参数
- OpenAI → `reasoning_effort` 参数

### 4. 功能保留
**错误转发**：保持errorBroadcaster功能
**Base64转URL**：保持createBase64File功能
**流式处理**：保持SSE流式处理逻辑

### 5. Gemini移除
**移除范围**：
- 配置文件：移除Gemini相关的配置项
- 转换器：移除Gemini相关的转换逻辑
- 测试用例：移除Gemini相关的测试用例
- 文档：更新文档，移除Gemini相关内容

## 风险评估

### 技术风险
1. 性能下降 → 优化转换算法，添加缓存机制
2. 上下文破坏 → 完整的测试用例覆盖，特别是上下文测试
3. 兼容性问题 → 保持API接口不变

### 业务风险
1. 用户体验下降 → 设置性能监控，及时优化
2. 功能故障 → 灰度发布，快速回滚机制
